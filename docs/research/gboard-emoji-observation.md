# Gboard emoji-pane observation for Viipio v0.9.0 scope

**Evidence tier:** black-box observation of the installed Gboard **18.6.3.1002251336-release-x86_64** on one Android **15**, 720×1600 / 320 dpi emulator with Gboard selected; synthetic local `EditText` (`IME_ACTION_SEND`) and Android Settings search. This is not a specification of all Gboard versions, languages, apps or internals. No Gboard code, artwork, model, word list or screenshot is distributed as a Viipio asset. [Google's Gboard Help](https://support.google.com/gboard/answer/2842292?hl=en&co=GENIE.Platform%3DAndroid) documents inserting one or several emoji and then tapping Send but does not identify whether Send belongs to the app or keyboard in every editor.

- Browse view: search entry, recent/category controls, an **ABC** return to letters and a lower-right **Backspace** were visible. No **Clear** and no dedicated **Send** appeared in the emoji browse pane on this setup. This does **not** prove no other configuration has those controls.
- Two successive emoji taps inserted two emoji into a local text field and kept emoji browse open. Lower-right Backspace removed the last emoji from the *editor* without leaving browse. The local test field initially had `😀😃`; one Backspace left `😀`. For a variation-selector sequence `♥️`, one Backspace removed the entire visible emoji, not only the selector.
- In the local `IME_ACTION_SEND` field, choosing emoji **did not trigger Send**. Tapping **ABC** returned to letters; the keyboard's Send action then invoked the editor callback (`IME_ACTION_SEND`, action ID 4). The test activity only displayed the callback/text and did not transmit a message. The host app may also offer its own Send button; this observation does not justify a fake Send button in emoji browse.
- Emoji search opened an internal query view with letter keys; querying `heart` showed emoji results. Picking a result appended it to the host editor and left search open. Search Back returned to emoji browse. Query Backspace and browse Backspace have different targets; Viipio should keep the distinction while retaining its safe non-focusable search field.
- Viipio v0.8.0's visible **Clear** button only erased locally stored *recently used emoji*, not editor text. Removing that button from browse should preserve a deliberate privacy erasure path elsewhere, clearly labelled and separate from Backspace.

**Release acceptance for Viipio:** no Clear or bogus Send on browse; repeated picks, editor Backspace (including a multi-codepoint emoji), ABC→actual Send, search-query Backspace, recents and privacy erasure tested in a controlled installed editor. Keep normal text input and sensitive-field gates intact. Compare like-for-like screenshots without copying Google's visuals; restore Gboard and the emulator's original Home screen after probes.
