# Viipio v0.10.0 ranking: candidate protocol and release gates

**Status:** development candidate, not a released APK. Active input languages: Estonian (ET), English (EN). This document applies to `ViipioInputMethodService`, not inherited `CleverKeysService` or `SuggestionHandler`.

## Decisions

- Keep the CTC/geometric engine's candidates and scores, then consider a bounded top-1 promotion only when a rival has at least 65% of the current top score. Preserve each word's original decoder score and optional language label; never synthesize an unseen candidate or claim a decoder score is a calibrated probability. Other alternatives retain engine order.
- Remove **exact** `sis` only from the bundled ET CKDT V2 dictionary by deterministically transforming the pinned previous asset. Keep `siis`, `sisu`, `sisse`, every other canonical word and rank, and the EN lexicon. A personal user-entered `sis` remains an explicit user choice. This is a single justified lexical exclusion, not a general length cutoff. Update the ET manifest and test exact set/rank equivalence.
- The existing `en.cklm` from the attributed Leipzig/Tatoeba pipeline supplies EN *listed* continuation evidence for conservative swipe ranking, loaded off the UI thread. A missing/unavailable model leaves original order unchanged. A new ET CKLM candidate built from pinned Leipzig/Tatoeba data is included for **typed-suggestion reordering only**, after a next-word heldout test and attribution audit. No ET static *swipe* boost is enabled until the separate gesture replay and regression gate pass; local ET correction preference is independent of this corpus model.
- Optional correction learning is default OFF. The Settings → Corrections switch enables only explicit swipe-alternative choices, not passive typing or telemetry. A choice remains provisional until **the very next key is Space**: the write must succeed, the same editor must return the exact chosen word plus one space at the expected caret, and consent/erase revisions must match. Backspace Undo, next swipe/letter, cursor/field/language change, failed editor readback and sensitive/no-personalization fields do not teach. The credential-protected, app-private ET/EN store holds only bounded word-pair counts, no editor context or trajectory. Its separate file is outside the cloud/device-transfer allowlists; Settings offers explicit erasure. A net two confirmed choices are required before the preference can change top-1. The model and preferences must never be read in a forbidden field.
- Short-word typing suggestions remain choices, not automatic replacements; an exact keyboard-typed word is never changed by this feature. Synthetic rival pairs for both directions: ET `siis/sis` (lexicon exclusion), `tere/tee`, `töö/too`; EN `then/than`, `there/their`, `to/too`. Verify actual packaged dictionary membership for each testing pair before scoring.

## Evaluation before tag

1. Unit gates: corrupt score/language alignment, top-1 floor, listed vs unlisted context, no ET model, opt-in OFF, two-confirmation threshold, reverse-direction preference, storage faults, sensitive field, permission/backup boundaries, exact CKDT removal and manual suggestion independence.
2. Replay the same fixed, nonpersonal ET/EN paths and context candidates against the last published v0.9.1 and this candidate; count top-1, top-3, rival regressions, decoder fallback and affected cases by language. Do not report a selected or corrected sample as all-user accuracy. Retain failures rather than cherry-picking. Compare signed, installed APK outcomes with the pure-policy replay.
3. The earlier owner's 572 accepted ET diagnostic swipes were in an ephemeral document cache and **are no longer available on this host**. They cannot be silently recreated or used to quote a measured improvement. If a fresh owner-authorized copy becomes available, use only confirmed-intent rows for top-1/top-3 and only aggregate the private outcomes; neither accepted-only traces nor provisional Undo estimate all gestures.
4. Full `scripts/viipio-check.py full`, tracked-asset inventory, signed ARM64 APK metadata/certificate/permissions, in-place emulator update and controlled editor EN/ET, sensitive field, opt-in on/off/erase. Restore the original IME and foreground screen. A physical phone's accuracy, ergonomics, p95 latency and editor compatibility remain separate unverified gates.

## Reference comparison

A bounded Android 15 emulator black-box test in a synthetic English (UK) Gboard editor selected `from` as an alternative to `form`, deleted it and re-entered `form`; `from` remained an alternative, not an automatic replacement. One repetition does not characterize Gboard's learning policy. [Google's help](https://support.google.com/gboard/answer/12373137?hl=en) describes personalization and clearing learned data; its [suggestion help](https://support.google.com/gboard/answer/7068415?hl=en&co=GENIE.Platform%3DAndroid) documents removing a suggestion. No Gboard code, model, data or assets were copied.
