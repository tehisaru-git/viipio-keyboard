# Viipio local swipe diagnostics (experimental)

Open **Viipio Settings → Privacy & diagnostics → Swipe diagnostics**. Swipe collection and the separate **manual completed-word diagnostics** both default **OFF**. Starting one does not start the other. Read the applicable consent dialog and tap **Start local collection** for swipe data or **Start manual word diagnostics** for completed Viipio-keytyped Estonian words. Swipe diagnostics store accepted *Estonian swipe* paths in ordinary text fields, their key geometry, top suggestions and committed words. A verified Backspace removal is marked as `undoObserved` immediately; it is not called a final deletion unless the keyboard can still verify that state. An alternate candidate or manually retyped replacement can then be linked to the same swipe. The manual diagnostic stream uses distinct `estonian-manual-v1` JSONL rows with `word` and optional `swipeId`, never a fabricated swipe path. Ordinary manual typing unrelated to a swipe is logged only when manual consent is ON and the IME has verified a completed word typed entirely with its own keys and followed by a literal space. Merely reading an editor's text is never grounds to collect a word. A linked `swipeId` requires the just-undone owned swipe to resolve to exactly that key-typed replacement; older or unmatched edits stay unlinked. New `estonian-swipe-v2` rows can additionally carry aligned 0–1000 candidate display scores, the actual `ctc`/`geometric` decode route and the app version; older v1 rows remain readable. Scores are not calibrated correctness probabilities. Some editor updates cannot be verified, so a row may have no final word; do not interpret that as an unchanged word. Collection works across ordinary apps, not only the separate Swipe study screen.

**Privacy:** An ordinary text field may contain personal words; test with nonpersonal phrases and review any exported file. Password, email, URL, numeric, incognito and no-learning fields are excluded. English words and swipes are not recorded by the older swipe/manual streams; the separate input-events stream can include ET and EN confirmed keyboard input when explicitly enabled. There is no automatic phone-to-server link, upload, Android Internet permission or collection of surrounding editor contents. Events are stored in app-private, no-backup files, each encrypted with an Android Keystore AES-GCM key; a bounded in-memory representation exists while the keyboard process runs. Exports contain at most the latest 5,000 swipes and 5,000 manual words from the last 30 days. Encrypted append-only segments together use at most 48 MiB; expired or evicted records can remain encrypted in a partly used segment until that segment rotates or you tap Erase. The exported JSONL strips source-app package and field identifiers from swipe rows; manual rows never store those identifiers. Neither consent marker nor the encrypted file is in cloud/device backup allowlists.

Tap **Stop all diagnostics** to revoke all three consents and stop new events while keeping existing data. Tap **Erase local data**, then confirm, to stop and remove all three consents, the encrypted store and key; it cannot delete files you previously exported. If a store is corrupted or its key is lost, the keyboard disables recording rather than silently resetting the store; use Erase to recover.

To send a test file for analysis:

1. Tap **Export JSONL file** and choose a local location, for example **Downloads**. This creates a **readable plaintext file** only where you chose; avoid a cloud-backed document provider if you want it to remain local. The export is not sent to the developer automatically. The separate **Swipe study → Export JSON** saves a different, prompted in-memory test session.
2. Review the file yourself before sharing; a swipe word may be personal. Connect and unlock the phone via USB. Use Android's file-transfer mode to copy the exported file, or, if *you* authorized ADB debugging and saved to Downloads, use `adb devices -l` followed by `adb pull /sdcard/Download/viipio-diagnostics.jsonl DESTINATION` on the receiving Linux computer. Check the actual document-picker filename/path first. USB connection alone does not grant the server access to app-private encrypted files or this export.
3. Send or analyze only the chosen export. JSONL contains one object per accepted swipe, with normalized path coordinates and time offsets, keyboard dimensions/key rectangles, candidates, the committed word, corrections and (where verified) a final word or deletion marker. If manual consent was separately enabled, distinct `estonian-manual-v1` objects contain a completed Viipio-keytyped word and an optional verified same-field direct-undo `swipeId`. New `estonian-swipe-v2` objects may include aligned candidate display scores, decoder source and app version. The swipe/manual rows do **not** contain raw model logits or a recording of everything you typed; separately enabled input-event rows may contain the keyboard's own typed sequence. When done, erase local data and any exported copy you no longer want.

The feature and swipe accuracy remain experimental. It has not been benchmarked by human-finger Pixel 8 trials. Avoid using this test keyboard for secrets or important messages until you have checked it in your own apps.

## Separate Viipio input events (experimental)

**Start Viipio input events** is a third, independently confirmed consent, OFF by default. This stream is not the Estonian-only swipe/manual streams. The active IME calls `TelemetryRuntime.recordInputEvent(context, event, editorInfo)` only after a Viipio-owned action has passed same-field/caret and exact bounded readback checks; permitted ET/EN ordinary-field actions include own-key commits, swipe commits, candidate replacements, one-code-point deletions and language changes. It does not pass editor context, paste/clipboard text, emoji-search queries, or arbitrary app text. It stores `viipio-input-v1` JSONL rows with bounded own text (or deletion length), session ID, sequence number, relative time, language, kind, source and outcome. No app package, field ID, device ID or surrounding editor text is retained in these rows. It excludes sensitive variations, private/incognito/no-suggestions/no-personalized-learning fields. A strict 64-character printable keyboard-owned text alphabet applies; unsupported characters and uncertain actions are omitted, so this is not a literal copy of every key or every app edit.

The in-memory queue holds at most 128 pending actions, schedules at most one immediate and one delayed flush, and writes one encrypted frame/fsync per batch; pending items are discarded on Stop/Erase. The replay/export window is the latest 10,000 input events within 30 days, subject to the common 48 MiB encrypted-segment cap. This is a **retained window**, not a complete lifetime log: overflow, expiration, crashes and whole-segment eviction can leave unknown gaps, and a reliable cumulative lost-event total is not shown. Sequence numbers within a retained session may expose some gaps, but entire removed sessions cannot be reconstructed. Export first flushes pending actions, then writes plaintext **only** to the user-selected document. A failed SAF write attempts to delete or truncate its partially written document, but the provider may leave readable plaintext; the UI warns the user to check and delete it manually. Exported input text can contain personal material: review before sharing and delete exported copies yourself. The active service path and storage have scoped unit tests; the installed signed v0.6.0 ARM64 APK also passed synthetic ordinary-field swipe→Undo→manual-link export, Stop/Erase/restart and numeric-PIN exclusion checks. Physical Pixel 8 behavior, all third-party editors and long-duration collection remain unverified.
