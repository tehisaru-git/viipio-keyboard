# Viipio keyboard v0.10.3 — key-feedback refinement

**Status: Published.** [GitHub release v0.10.3](https://github.com/tehisaru-git/viipio-keyboard/releases/tag/v0.10.3) is a normal latest release with one signed ARM64 APK. Android App ID remains `io.github.tehisaru.viipio`; the active input languages are Estonian (ET) and English (EN). The tested tag points to `df06f81ed4170e9e42c3a70679ba2c6ebb2b2577`; its candidate record honestly said “NOT published” when tagged. This living main-branch record was finalized after public readback without moving the tag or replacing the APK.

## Scope

- On the ordinary ET/EN letter and symbol pages, short-tap letter, top-row digit and symbol bubbles are sized and positioned against a bounded Gboard 18.6.3 Android 15 emulator observation: approximately 52–55 dp in diameter, with the bubble centre roughly 54 dp above the touched key centre when room permits. The top digit row uses the existing toolbar space and remains inside the IME's top edge. Preview glyphs are fitted to the bubble, including at increased system font scales.
- In separate PIN and integer numeric editors, the reference showed **pressed-key shading without a floating character bubble**. Viipio now gives digits and numeric separators transient pressed-key shading on dedicated numeric layouts, preserving the existing editor-specific privacy gates. Ordinary text-password letter previews remain separate from numeric PIN behavior.
- The default-on **Settings → Preferences → Key pop-up** switch still controls floating previews; numeric pressed-key shading remains basic tap feedback even if the switch is off. Short taps, long-press alternatives, glide cancellation, ET/EN routing, suggestions and offline behavior must not change.

## Release verification

- A focused red→green native-graphics regression for the first-row bubble and a red→green numeric-editor pressed-key regression preceded the fix. The final guarded full JVM run had **5,718 cases across 539 suites: 5,705 passed, 0 failures, 0 errors and 13 skipped**; the 48 Viipio Python tests passed. The 13 skips are not passes. A separate 238-test, 19-suite targeted run had 0 failures/errors/skips. A read-only independent review found no remaining code/security blocker and its documentation-status finding was corrected.
- The signed ARM64 APK `ViipioKeyboard-v0.10.3-arm64-v8a.apk` is **23,005,424 bytes**, SHA-256 `a41e01a8d9c69e7d9fb941425ae7244be0b4e946a2abfa718280406bef4ef90c`. `apksigner verify` passed; the certificate SHA-256 is `4cb4830a8f0832481ecb91dfdfc6f620da5f0f155b6afdc199a40589ff478838`, the established Viipio release signer. `aapt` reports `io.github.tehisaru.viipio`, `0.10.3`, ARM64 versionCode `10032`, ABI `arm64-v8a`; merged permissions do not include INTERNET or RECORD_AUDIO. All **59** source assets in `src/main/assets/` matched members of the signed APK byte-for-byte; its **70** packaged assets include `assets/licenses/NOTICE.txt`, byte-identical to root `NOTICE`.
- The signed APK installed **in place over v0.10.2** on the shared emulator. With Key pop-up ON, short taps in a controlled Settings search field committed exact synthetic `2e`; video frames visibly showed the enlarged `2` and `e` above their keys, the first-row circle fully visible and toolbar controls intact. The symbols page displayed `@` temporarily and committed exact `@`. In the disposable numeric PIN editor, short `2` shaded only its key during the press, then restored its normal fill, without a floating bubble. Turning Key pop-up OFF removed the top-row `2` bubble in sampled frames while an exact `2` still committed; ON was then restored and visually read back. The numeric probe and debug APK were removed, and the initial Gboard default IME and Home foreground were restored. The public-suitable synthetic [key-feedback crop](../screenshots/v0.10.3-key-feedback.png) contains only keyboard artwork, no personal text.
- A further signed-APK check switched to **EN** in Settings search: short `e` showed the same transient bubble and committed exact `e`. In a disposable synthetic **text-password** editor, short `e` also showed its key label briefly; the field masked it, no suggestions appeared, and its Send action reported length 1. Only synthetic input was used; that editor was uninstalled, ET restored, the search cleared, and Gboard/Home restored again.
- The public release API reported `v0.10.3` as non-draft, non-prerelease and `releases/latest`, with exactly one ARM64 asset of **23,005,424 bytes**. A fresh **unauthenticated** download was byte-identical (`cmp`) to the locally installed signed APK, with matching SHA-256, package/version/ABI, `apksigner` certificate and no INTERNET/RECORD_AUDIO permissions. The older `v0.10.2` release still has its original one named APK. The release tag remains at the tested commit, not the later documentation-only update.

## Limits

Gboard measurements are from one emulator configuration, not a universal implementation specification. No personal password was entered or recorded; only the single synthetic character was used in a disposable local editor. Human physical-device touch perception, timing, real-finger swipe quality and ergonomics were **not** measured in this refinement. Keep another keyboard available and review important text. A secure off-host backup of the release signing key has not been confirmed.
