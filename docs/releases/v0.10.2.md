# Viipio keyboard v0.10.2 — key-press preview verification

**Published GitHub Release:** [v0.10.2](https://github.com/tehisaru-git/viipio-keyboard/releases/tag/v0.10.2), a normal release (latest when published) with one signed ARM64 APK. The public asset was downloaded without authentication and matched the tested local APK byte-for-byte. Android App ID remains `io.github.tehisaru.viipio`; active languages remain Estonian (ET) and English (EN). The tested APK reports versionName `0.10.2` / versionCode `10022`.

## Shipped scope

- Show an enlarged, original Viipio-drawn label near a physical letter, digit, symbol or punctuation key while it is pressed. The transient indicator does not commit text and is removed on release, cancellation, glide, long-press replacement, editor/language/page change or view detach. Shifted letters preview their current uppercase label. A narrow/edge key stays within the existing measured keyboard surface.
- The active Settings → Preferences page has a separate **Key pop-up** switch, enabled by default and independently persistent. Off hides only the preview, not normal typing or long-press choices. Existing Gboard-like 300 ms (adjustable) held-choice delay remains unchanged. This does not add sound/vibration settings.
- The controlled reference keyboard also showed temporary character pop-ups on `2`, `@` and in a synthetic password editor; Viipio renders only the pressed key's existing label there, without unlocking suggestions, recording editor text or changing privacy policy. Observation/spec: [Viipio key-press preview](../specs/viipio-key-preview.md).

Merged permissions add neither INTERNET nor RECORD_AUDIO. All 70 packaged assets are byte-for-byte identical to the previously verified, publicly downloaded v0.10.1 asset; no asset inputs changed.
- Installed the new signed APK **in place over v0.10.1** on `emulator-5554`, preserving app data. Settings → Preferences visibly showed **Key pop-up ON** before a write. Switching OFF and restarting the Viipio process read back unchecked; the same normal editor accepted exactly `sasa` and no enlarged bubble was visible in 20 sampled frames. Switching ON and restarting read back checked. In ET, four measured short taps accepted exactly `sasa`; a larger `a` bubble was visibly captured (`build/tooling/v0102-key-preview/viipio-et-popup-sheet.png`, frame 13). The `m` hold showed its existing `?` alternative **without** overlapping the enlarged letter preview, then committed exactly one `?`. In a disposable password editor, eight synthetic letter taps displayed transient enlarged letters in the sampled video, produced eight masked characters and **no personal-word Add/candidate**; no real password was used or stored as evidence.

## Limits

Synthetic emulator touches and low-frame-rate video cannot measure a human finger's perceived duration, physical-device latency or real-app compatibility. Extremely large system fonts can make the popup cover several keys; the source keeps the same 286 dp keyboard-view height, but physical-device usability is untested. The long-lived Viipio signer must remain private and requires a secure off-host backup, which has not been confirmed. This is an experimental, not production-readiness, release.
