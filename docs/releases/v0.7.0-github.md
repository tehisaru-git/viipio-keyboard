# Viipio keyboard v0.7.0 — experimental new-app test release

**A new Android app, not an in-place update.** v0.7.0 uses App ID `io.github.tehisaru.viipio`; v0.6.0 and all earlier releases use `io.github.tehisaru.estonianswipe`. The visible app and keyboard picker name remains **Viipio keyboard**. A new Viipio-named release signing certificate is used for this new package; the old signer, old APK and historical release data remain unchanged. Sharing a GitHub repository does **not** transfer installed app data or make the packages mutually updatable.

**ARM64 asset:** `ViipioKeyboard-v0.7.0-arm64-v8a.apk` (SHA-256 `443962e74f433ffcc68a0b5965b750c76f2680b87a3299721879dc24e536679d`). New signer certificate SHA-256: `4cb4830a8f0832481ecb91dfdfc6f620da5f0f155b6afdc199a40589ff478838`. The old APK stays under its old tag. Current input languages remain separately selected Estonian (ET) and English (EN); the product identity is language-neutral.

## What changed

- A neutral installed package ID, active IME component/label, app-shell theme and reproducible icon-generator name; the suggested local diagnostics export filename is `viipio-diagnostics.jsonl`.
- Existing offline typing, separate ET/EN selection, explicit personal-word Add/Undo, specialized PIN/number layouts and *separately opt-in* swipe/manual/input-event diagnostics carry forward. Diagnostic storage and old package preferences do not migrate between apps. Sensitive-field exclusion is unchanged.

## Install and privacy

Keep Gboard or another fallback keyboard enabled. Install the new APK *alongside* the old Viipio app, enable and select the new keyboard separately, and test it before uninstalling the old app. Re-enter wanted settings and personal words; automatic app-data migration is not provided. Old diagnostic data remains in the old app. A deliberately exported JSONL file is **plaintext that may contain personal text**, not a general app-data backup. Diagnostic consents in the new app start OFF. In Obtainium, the old tracked entry may remain bound to the old App ID. Check the downloaded APK's new App ID; if necessary, add the repository `https://github.com/tehisaru-git/viipio-keyboard` as a separate tracking entry. If duplicate sources are refused, remove only the old tracking entry—not the old installed app—then add it again. The actual Obtainium transition has **not** been verified on the owner's device.

## Test scope and limitations

- The Python Viipio quick suite passed **36/36**; the targeted Android JVM batch passed **151/151** on the new ID/service source.
- The completed full Android JVM suite is still **red**: 5,591 tests, 41 failures, 13 skipped. All 41 failed class/test identifiers match the v0.6.0 final-run log; that does not make the failing behavior safe or the suite green.
- Pixel 8 / GrapheneOS real-finger Estonian swipe accuracy, latency, ergonomics and third-party-editor behavior have not been measured. **Keep another keyboard installed and review important text before sending.**
