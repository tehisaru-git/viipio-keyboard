# Viipio keyboard v0.9.0 — release verification record

**Candidate, NOT published at preparation time.** This source declares `0.9.0`, Android App ID `io.github.tehisaru.viipio`, and active input languages Estonian (ET) and English (EN). The built, signed APK and public GitHub Release must be checked independently before this record is marked published. Earlier release tags and assets are immutable.

## Emoji browse changes

- In the emoji browse footer, **Clear** (which erased only recently used emoji, not editor text) is replaced by a genuine **Backspace** for the current editor. The callback refuses a stale editor, input connection or keyboard view; selecting emoji still leaves the inline browser open for further choices.
- Backspace uses a bounded grapheme-aware readback so one tap removes supported variation-selector emoji, skin-tone emoji, ZWJ sequences and flags as a visible unit. It preserves selections and avoids blind deletion from an empty/unreadable editor. For an unanchored or truncated pre-cursor window (including an editor that returns fewer units than requested), it may safely decline instead of deleting an uncertain grapheme or regional-indicator pair. Android/ICU Unicode-version coverage can differ across devices.
- The browse footer has **ABC** to return to the ordinary keyboard; it does **not** add a fake Send action. In editors that advertise `IME_ACTION_SEND`, the actual Send belongs to the ordinary keyboard/editor action path. Emoji search keeps its *query* Backspace separate from the browse footer's *editor* Backspace. The browse footer controls have at least 48 dp height.
- The active **Privacy & diagnostics** screen provides a separately confirmed **Clear recently used emoji** action. The saved local history is removed only after persistence succeeds; a retained emoji browser reloads it on reopening. This action does not delete the host editor's text or erase separately consented diagnostic data.

The [bounded Android 15 Gboard emulator observation](../research/gboard-emoji-observation.md) is a behavioral comparison on a synthetic editor, **not** evidence about every Gboard build or proprietary implementation.

These are source checks, not installed editor proof.
- **Installed signed editor:** `adb install -r` accepted the v0.9.0 ARM64 APK over installed v0.8.0 (8002→9002) without uninstalling. In a disposable local-only `IME_ACTION_SEND` editor, two emoji picks yielded `😀😀` while browse stayed open; browse Backspace left `😀`; ABC then the ordinary Send key invoked action ID 4 with text `😀` and did not transmit a message. A separate search typed `süda`; query Backspace changed only the query to `süd` while the host editor stayed empty. Selecting the first result committed `❤️`; closing search returned to browse, whose Backspace removed the entire heart sequence. The editor remained visible above the inline emoji pane. UIAutomator omitted the IME's custom browse rows, so screenshots were checked along with exact editor readback.
- **Privacy:** the active Privacy & diagnostics page showed diagnostics OFF and a separate recent-emoji erasure action. Cancel did not show success; confirming displayed `Recently used emoji cleared`. On reopening the installed emoji browser, the recent section and its synthetic `❤️`/`😀` items were absent. The disposable probe app was uninstalled; the prior Gboard default, its originally disabled Viipio state and the launcher Home screen were read back after the tests. The no-network probe is not a real messaging-service test.
