# Viipio keyboard v0.8.0

Experimental offline Android keyboard, with separate Estonian (ET) and English (EN) input languages. Keep Gboard or another fallback keyboard available while testing.

## What changed

- A glide starting just inside the lower number-row boundary can be accepted when it continues as a real letter-to-letter swipe; number-row points are left out of decoding. Ordinary number taps remain taps.
- Bounded suggestions for a prior word support caret-in-word, whole-word one-edit alternatives. Choosing one requires an unchanged editor context and exact readback of the word to replace; otherwise nothing is replaced. These are suggestions, not automatic rewrites.
- Explicit personal-word **Add/Undo** requests a background CTC refresh. If the next swipe starts before it finishes, that swipe may still pay the new trie-build cost; it does not intentionally use an obsolete lexicon.
- An [EKI ENC 2021 frequency reference](https://github.com/tehisaru-git/viipio-keyboard/blob/v0.8.0/docs/research/eki-enc21-common-word-forms.md) is documented under CC BY; its CSV is research-only, **not included as a new app dictionary or ranking change**. Google keyboard behavior is a comparison reference, not a source of proprietary code or assets.

## Install and privacy

From v0.7.0, download `ViipioKeyboard-v0.8.0-arm64-v8a.apk` and install it **over** the existing app; do not uninstall v0.7.0. This APK was verified to keep App ID `io.github.tehisaru.viipio` and the same release certificate, with a higher versionCode `8002`; Android accepted an in-place emulator update. A separate signed v0.8.0 reinstallation retained a synthetic personal word. The first *cross-version* personal-word readback was interrupted by a Settings UI failure, so personal-word/settings retention on a Pixel 8 has not been independently confirmed here; check your settings after updating. Keep Gboard available. v0.6.0 and older use a separate App ID and are not updated in place.

Diagnostic collection remains separately opt-in for swipe, manual-word and input-event data. In the installed signed APK, a numeric-password field produced zero records even with all three collections deliberately ON; Stop/Erase returned them to OFF/zero. User-chosen JSONL exports are plaintext and can contain personal text. No user diagnostics were used for the EKI corpus reference.

## Verified source tests and remaining release gates

- Candidate source: **5,601 JVM tests, 0 failures, 0 errors, 13 skipped** across 530 suites; 36 Viipio Python tests and 1 EKI parser test passed. Four bounded Android instrumented tests also passed on a separate debug app, including an isolated personal-word trie refresh test. The skipped tests were not run. Neither the instrumentation nor these source tests prove physical-device swipe accuracy or immediate post-save latency. The historical v0.7.0 tagged source had a red full run; later post-release `main` was green.
- Signed ARM64 APK: `ViipioKeyboard-v0.8.0-arm64-v8a.apk`, SHA-256 `087a8f7484b654b27f6fbb9b3dab241d1e116c8976694f3910d074a096ddfcaa`, package `io.github.tehisaru.viipio`, versionCode `8002`, certificate SHA-256 `4cb4830a8f0832481ecb91dfdfc6f620da5f0f155b6afdc199a40589ff478838` (**same signer as v0.7.0**). `apksigner verify` passed; no `INTERNET` or `RECORD_AUDIO` permission. Compare the downloaded asset against this SHA-256.
- Synthetic debug-IME UI: a stationary number-row tap inserted a digit; a near-boundary glide inserted an alphabetic word without a digit. Moving the caret into `tere trre homme` offered `tere`, and explicit selection yielded exactly `tere tere homme`. These are controlled emulator results, not a human-finger quality benchmark.
- Explicit personal-word UI: synthetic `zqzq ` showed **Add zqzq to Estonian (ET) words**; tapping it displayed **Added zqzq · Undo**, and Undo removed the entry. In a separate emulator run the very next injected swipe committed `zqzq tere`; no reliable latency distribution was measured.
- Installed checks: the separate debug-IME probes left the published apps untouched; a signed `adb install -r` then updated v0.7.0 (7002) to v0.8.0 (8002) in place with no uninstall, retaining the separate v0.6.0 package. The first cross-version personal-word readback was interrupted by a transient Settings UI failure, so do not call that specific retention test passed. A separate signed v0.8.0 reinstall **did** retain a synthetic ET personal word; it was removed afterward. In a numeric-password field, all three consented diagnostics stayed at zero rows, and Stop/Erase restored OFF/zero. Gboard and Home were restored.
- Physical Pixel 8 / GrapheneOS finger accuracy, immediate post-Add swipe latency, battery use and third-party-editor behavior remain **unmeasured**. Keep another keyboard available and review important text before sending.
