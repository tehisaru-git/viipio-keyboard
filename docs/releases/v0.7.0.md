# Viipio keyboard v0.7.0 — neutral Android App ID

**Pre-publication verification snapshot:** at the time of this record the APK was **NOT published**; check the [GitHub release page](https://github.com/tehisaru-git/viipio-keyboard/releases/tag/v0.7.0) for current availability. This is a *new Android app*, not an in-place update to v0.6.0. Its package ID is `io.github.tehisaru.viipio`; releases through v0.6.0 used `io.github.tehisaru.estonianswipe`. The visible app/IME name remains **Viipio keyboard**. The current typing languages remain Estonian (ET) and English (EN), selected separately; the product identity is not restricted to either language.

## Scope

- Replace the Android App ID and active IME component name with language-neutral Viipio identifiers; keep the Kotlin/R namespace and licensed CleverKeys-derived decoder internals unchanged.
- Use a new **Viipio keyboard** release-signing certificate and private key kept outside Git for this new package. The v0.6.0 signer and APK stay unchanged; the new keystore/password must be backed up securely off-host so future `io.github.tehisaru.viipio` releases remain updatable.
- Use a neutral default JSONL export filename while preserving existing Estonian-specific swipe/manual schemas and separate ET/EN input-event schema. All three diagnostic consents remain independently OFF by default, and sensitive-field exclusions are unchanged.
- Keep the v0.6.0 and older tags/APKs and their original checksums as historical records. Do not edit them into a fictional in-place update.

## Migration and privacy

The two APKs have separate Android sandboxes and may coexist. Do **not** uninstall the old keyboard before confirming that the new Viipio IME can be enabled, selected and used, with another keyboard as fallback. App settings, personal words, current keyboard selection and encrypted diagnostic data do not transfer automatically. If you choose to export old diagnostics, review the plaintext JSONL and keep it safe; this is **not** a general app-data backup. Re-enter wanted personal words/settings in the new app. In Obtainium, an existing tracked entry bound to the old App ID may not convert to the new app; add the same repository URL as a new entry. If duplicate sources are refused, remove **only its old tracking entry, not the old installed app**, then add the source again and check the new App ID before installation. Do not assume Obtainium performs a data migration.
