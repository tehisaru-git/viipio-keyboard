# Viipio keyboard v0.6.0 — personal words and input evidence

**Published GitHub Release — experimental owner test, not production-quality certification.** Keep another keyboard installed. This release preserves the package ID and developer signing identity; the signed update was installed on the shared emulator, not on the owner's Pixel 8. Current languages are Estonian (ET) and English (EN). The downloadable ARM64 artifact is `ViipioKeyboard-v0.6.0-arm64-v8a.apk`.

## Changes since v0.5.1

- A word typed wholly with Viipio letter keys and ended by a literal Space can show an **Add to Estonian/English words** action in the existing 48 dp toolbar area. Tap the action to add it explicitly; **Undo** removes that new entry. The Settings → Languages & personal words list remains available. No passive word learning or change to the default swipe ranking.
- **Start manual word diagnostics** and **Start Viipio input events** are separate from **Start local collection** for swipes; all three default OFF and enabling one does not enable another. Manual diagnostics may store completed Estonian key-typed words in ordinary text fields as `estonian-manual-v1` rows; it does not log every key or surrounding app text. A linked swipe ID requires immediate owned-word Backspace undo, same-field key-typed replacement and verified resolution. Unmatched/older edits stay unlinked; an undo alone is provisional. The input-event stream may store bounded, confirmed Viipio-generated ET/EN commits, swipes, candidate replacements, deletes and language changes as `viipio-input-v1` rows, with separate consent. It omits unsupported characters, emoji/search/clipboard, unverified writes and excluded editor fields. The latest retained events can have gaps after overload, retention or segment eviction; the total number of lost events is not reliably knowable after restart, so no lifetime drop counter is claimed. It is **not** a literal copy of all app text. **Stop all diagnostics** revokes all three consents; Erase removes local data and keys. A failed consent-marker deletion leaves a durable revocation marker so a restart cannot silently re-enable recording when storage is writable.
- New swipe rows use `estonian-swipe-v2` *only when* candidate display scores are aligned and bounded. They include the actual CTC/geometric decode route and app version. Older v1 rows remain readable; neither score is a calibrated accuracy probability. The user-selected JSONL export remains plaintext and may contain personal words; no network upload was added.
- The separate in-app, fixed-prompt Swipe study now includes `siis`, `sis`, `mhm` and `mhmh` as nonpersonal test targets. The general ET lexicon, default ranking and ET/EN language separation are unchanged.
- Numeric-password PIN editors now show a 3 × 4 digit-only keypad with Backspace, `0` and Enter on the bottom row. Ordinary number, decimal/signed number, phone, date, time and date-time editors use their own numeric layouts and appropriate available separators instead of QWERTY. Numeric editors hide the suggestions/emoji toolbar, and field changes cancel pending held-key repeats. The keyboard artwork follows a bounded UI comparison; PIN contains no punctuation or word learning.

## Slang-vocabulary gate

No chat-slang pack is silently bundled. A [University of Tartu spoken-Estonian frequency dataset](https://doi.org/10.23673/RE-463) is published as CC BY 4.0 and gives evidence for colloquial `mhm`/`mhmh` in speech, **not their frequency in present-day private chats**. The [teen-language corpus](https://doi.org/10.23673/RE-455) has restricted conversation files and CC BY-NC-ND metadata, not a public redistribution grant for a keyboard pack. Obtain appropriately licensed chat-register per-form counts, review spelling and provenance, then evaluate a small opt-in overlay against rival-word regressions before considering distribution. Users can add the two forms personally now.
