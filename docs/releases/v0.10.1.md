# Viipio keyboard v0.10.1 — candidate verification

**NOT published.** The current public release remains v0.10.0. This is the candidate record for a separate v0.10.1 release, not a replacement of the v0.10.0 tag or APK. Android App ID remains `io.github.tehisaru.viipio`; the active input languages remain Estonian (ET) and English (EN).

## Intended scope

- Show an explicit `+ Add “word” · ET/EN` action while a word is being typed on Viipio's own keys, in the same 48 dp bar as the three existing scrollable suggestions. When no candidates are present, keep the full-width Add row. Keep the v0.10.0 post-Space offer as a fallback.
- Check the exact word, cursor, input connection, editor, language, eligibility and dictionary absence again at the tap. Save only on an explicit tap to the existing credential-protected ET/EN personal-word store; an ordinary letter or Space does not save a word, and Add does not change the editor text. Exclude sensitive/private/no-personalization fields.
- Provide an immediate Undo action; retain it when a durable removal fails. Teach `+ Add` once with a nonblocking generic first-use hint, and keep the steps visible under Settings → Languages & personal words. The hint stores a boolean only and is excluded from backup/transfer alongside personal words. Added words may join the existing personal suggestion/lexicon path; a single addition does not change the top-1 swipe ranking by itself.

## Limits

Do not infer human swipe accuracy, physical-device latency or Gboard implementation details from synthetic keyboard tests. The personal-word and hint preferences are not included in automatic backup; reinstallation can require re-entry. A secure off-host backup of the signing key has not been confirmed. The one-time hint was visibly checked on a fresh debug package in one emulator viewport, not replayed on the already-used release package or across narrow/split-screen layouts. A field switch before the popup's first frame could consume its shown flag; the help remains permanently available in Settings. On a durable Add/Undo write failure the button remains retryable and does not claim success, but Android may suppress the accompanying Toast error message when notifications are disabled.
