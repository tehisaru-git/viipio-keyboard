# Viipio keyboard v0.9.1 — local candidate verification

**Local candidate; NOT published.** Source version `0.9.1` retains Android App ID `io.github.tehisaru.viipio` and the active input languages Estonian (ET) and English (EN). The current public release is v0.9.0; this document does not provide an Obtainium update. Old tags and APKs remain unchanged.

## Scope

- The offline emoji browser has one continuous, vertically scrolling catalog. The selected category follows the first visible section; tapping a category jumps to it. Ordinary emoji rows use eight unboxed cells. Long kaomoji have two wider, smaller-text cells rather than eight clipped fragments.
- Skin-tone variants from the **existing packaged catalog** share one browse cell. Hold it to reveal the available choices. Simple hands have neutral plus five tones; mixed-person ZWJ families keep all packaged variants in a scrollable popup, including sequences beyond the sixth choice. No missing Unicode sequence is synthesized. A confirmed uniform choice sets a local default for compatible hands, including neutral forms that carry VS16. Search remains separate and can still find catalog variants.
- A popup closes on an outside touch, a different emoji selection, scrolling or pane dismissal; touches in its blank interior are consumed. A successful choice updates recents and the tone display in one list rebind so the viewport does not jump backward. Storage exceptions after an editor-confirmed commit do not crash the IME; a failed tone preference write does not falsely change the global default.
- The ordinary keyboard's original drawn emoji icon is larger **inside the same key bounds**. No Gboard artwork, implementation, models or assets were copied. The [bounded Gboard behavior observation](../research/gboard-emoji-scroll-tone-observation.md) is from one Android 15 emulator; it is not a universal visual or functional equivalence claim.

## Limits and update safety

The intended ARM64 versionCode is `9012` (v0.9.0 ARM64: `9002`); in-place updating still requires the same private signing certificate and Android accepting `adb install -r` without uninstalling. A local debug APK uses a different signer and App ID and must not be used as a release update. Physical Pixel 8 / GrapheneOS touch, performance, font rendering, accessibility-service behavior and third-party editor behavior remain unverified until exercised there. The long-lived signing key must remain outside Git; a secure off-host backup has not been confirmed.
