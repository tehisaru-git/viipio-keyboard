# Viipio keyboard v0.8.0 — release record

**Pre-publication verification snapshot:** v0.8.0 was **NOT published** when this record was prepared. Check the [release page](https://github.com/tehisaru-git/viipio-keyboard/releases/tag/v0.8.0) for current availability; publication and public-byte comparison are documented below only after readback. This source declares version `0.8.0` and App ID `io.github.tehisaru.viipio`; actual APK identity and signer are verified in the artifact section. The active input languages are Estonian (ET) and English (EN).

## Scope

- A genuine letter-to-letter glide that begins near the lower edge of the number row can start at its first letter; number-row samples are excluded from the decoder path. Stationary number taps remain taps. This is a bounded boundary case, not permission to decode arbitrary digit-start gestures.
- Manual suggestions can propose bounded one-edit alternatives for an earlier word when the caret is moved into it, using the whole word rather than only the fragment before the caret. A tap checks that the editor and surrounding text still match, selects the exact original span, and reads back the selected text before replacement; otherwise it declines the edit. Suggestions are not automatic corrections or a guarantee of finding the intended word.
- Successful explicit personal-word **Add** and **Undo** now request a background CTC refresh after persistence. If the next gesture starts before it finishes, decoding may still pay for a new trie build; the old version is not intentionally reused for that gesture. No immediate-next-swipe latency guarantee or passive learning is implied.
- The [EKI ENC 2021 word-form frequency CSV](../research/eki-enc21-common-word-forms.md) is a documented, CC BY-attributed **research reference only**. It is not a shipped dictionary or a change to swipe frequency ranking. Behavior comparisons with Google keyboards refer to observed behavior, not copied proprietary code, models, dictionaries or assets; see the [initial swipe research](../research/estonian-swipe-initial.md).

## Update and privacy

v0.7.0 and v0.8.0 share Android App ID `io.github.tehisaru.viipio`. `aapt` and `apksigner` verified that the v0.8.0 ARM64 APK has the same signing certificate as the anonymously downloaded [v0.7.0 APK](v0.7.0.md) (certificate SHA-256 `4cb4830a8f0832481ecb91dfdfc6f620da5f0f155b6afdc199a40589ff478838`) and a higher versionCode (`8002` versus `7002`). `adb install -r` accepted the in-place emulator update without uninstalling; check settings and personal words after updating on your own device. A debug-signed or differently signed APK is not an update path. Keep another keyboard enabled. The older v0.6.0 package has a different App ID and is not updated in place.

The existing separate swipe, manual-word and input-event diagnostic consents remain opt-in. In the signed APK, the tested numeric-password PIN field retained zero records even when all three collections were deliberately ON; other sensitive editor implementations were not exhaustively tested. No diagnostic export or personal text is published. A user-initiated JSONL export is plaintext and may contain personal text; handle or delete it accordingly. The EKI CSV is public corpus data, not collected user text.

## Pre-publication verification

- Python: **36 Viipio route/release tests + 1 EKI parser test, all passing**. The focused gesture, earlier-word and personal-refresh JVM suites passed **19/19, 14/14 and 8/8**.
- `python3 scripts/viipio-check.py full` completed **530 suites, 5,601 tests, 0 failures, 0 errors, 13 skipped** (`BUILD SUCCESSFUL in 12m 8s`). The 13 are skipped, not passed. This is the **v0.8.0 source candidate**, not a claim about a published APK. The v0.7.0 tagged source had 5,591 tests and 41 failures at its release; later post-release `main` had a green 5,592-test run. Those are distinct snapshots.
- Instrumentation: **4/4** bounded tests passed on `emulator-5554` with the separate v0.8.0 `.debug` package, including package identity, two context-learning privacy gates and an isolated CE personal-word Add/Undo → CTC trie invalidation/reuse check. The test package and debug app were removed; Gboard and both published packages were retained. This proves eventual memo refresh in isolation, **not** the time of an immediately following human swipe.
- Separate v0.8.0 debug-app UI probes on the shared emulator: a stationary number-row touch inserted exactly one digit; a glide beginning 2 px above the first letter row committed an alphabetic word without a digit; moving the caret into the earlier synthetic `trre` displayed `tere` as a candidate, and selecting it changed only `tere trre homme` → `tere tere homme`. Screenshots and exact editor readback were checked. The debug app was removed after each run and Gboard/home restored. This is not a human-finger accuracy or timing measurement. A stale-editor refusal is covered by JVM tests, not an installed third-party editor. Immediate post-Add swipe **latency** remains unmeasured.
- Explicit personal-word UI in a disposable debug app: tapping ET keys produced the unknown synthetic `zqzq ` and a visible **Add zqzq to Estonian (ET) words** action. Clicking it displayed **Added zqzq · Undo**; clicking Undo left no ET personal-word entry. In a separate run, a swipe immediately after Add produced `zqzq tere` in the editor and the synthetic entry was then removed via Settings. These checks prove the word and next swipe were not lost in this emulated sequence, **not** a latency distribution or guaranteed response time.
- Signed update/privacy: `adb install -r` accepted the v0.8.0 ARM64 APK directly over the v0.7.0 installation (7002 → 8002) with the same signer and without uninstalling; the separate v0.6.0 package stayed installed. A post-update Settings readback in that first run was transiently unavailable, so **cross-version personal-word retention was not directly confirmed by that run**. A separate signed v0.8.0 reinstallation retained a newly added synthetic ET personal word, which was then removed with both ET and EN absence checked. With all three diagnostics deliberately ON, a numeric-password editor accepted two digits while retaining zero swipe, manual and input-event rows; Stop/Erase returned all three to OFF and zero. The temporary numeric probe app was removed; Gboard/Home restored. These controlled checks do not replace Pixel 8 data-retention or real-finger timing verification.
- The locally signed ARM64 APK `build/outputs/apk/release/ViipioKeyboard-v0.8.0-arm64-v8a.apk` has **App ID `io.github.tehisaru.viipio`, versionName `0.8.0`, versionCode `8002`, label `Viipio keyboard`, ABI `arm64-v8a`, SHA-256 `087a8f7484b654b27f6fbb9b3dab241d1e116c8976694f3910d074a096ddfcaa`**. `apksigner verify` passed; certificate subject `CN=Viipio keyboard, O=tehisaru-git`, SHA-256 `4cb4830a8f0832481ecb91dfdfc6f620da5f0f155b6afdc199a40589ff478838`, identical to the anonymously re-downloaded v0.7.0 signer.
