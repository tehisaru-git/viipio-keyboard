# Viipio inline personal-word add (v0.10.1 candidate)

## Goal
Let a person save an exact unknown ET/EN word with one deliberate tap **during Viipio-owned typing**, without an interrupting modal, automatic saving, or replacement of any existing candidate. Keep the v0.10.0 after-Space offer and Settings word list as fallbacks. This is Viipio's own original interaction, not a claim about Gboard internals.

## Contract
- Eligible only for a normal, identified, non-private text field; reject password, email, URL, numeric, no-suggestions, no-personalized-learning and incognito/private modes **before** reading personal entries. No auto-learning from typed usage, swipe output, host-app text or opening the help.
- Track only successful Viipio letter commits in the active editor, connection and selected ET/EN language. A fresh collapsed absolute caret and exact bounded pre-caret word plus a verified nonletter/null-free right boundary must match at offer creation **and** at tap. A modified word, selected/moved caret, deleted character, changed editor, language, view, emoji/symbol mode or unreadable text revokes the old offer. A late dictionary load must not resurrect stale offers.
- When that exact word is absent from the current dictionary and personal list, show a pinned, at-least-48-dp `+ Add “word” · ET/EN` action beside the three intact, horizontally scrollable suggestion labels. The action wraps long words within the fixed-height bar instead of ellipsizing them; its accessible name also identifies the full word and language. It does not replace editor text. If no candidates exist, use the existing full-width `Add <word> to <language> words` row. An already known word never shows Add; failed dictionary load or storage read fails closed.
- The explicit tap performs a synchronous, bounded CE-only per-language write using the existing personal-word store and refresh callback, then offers **Undo** in the same fixed-height row. On failure, never claim success and retain a retryable offer. Undo removes only a successfully added word and only reports success if the removal succeeds; dismissal never deletes it. The action may disappear when typing resumes, but Settings retains the add/remove list. A single saved word may join candidate coverage; it is not itself evidence for a new swipe top-1 decision.
- Teach the affordance once without interrupting editing: on the first eligible pre-Space offer after at least three own letter commits (or the first completed unknown word if that happens earlier), show a generic short nonblocking hint about `+ Add` and Undo. Do not claim that a still-growing prefix is a complete unknown word; do not store it by showing the hint. Persist only a boolean that the hint was shown (no word, text or editor context), excluding it from automatic backup/transfer. The Languages & personal words Settings page always explains the same steps. The hint is not repeated on every unknown prefix.
- Keep the total IME height, toolbar access, selected language and all three candidate tap targets stable. No INTERNET/RECORD_AUDIO permission or background export.

## Acceptance gates
1. Red→green controlled `InputConnection` tests for unfinished exact owned words, known/duplicate entries, partial or changed suffix, moved caret, unreadable editor, Backspace, ET/EN isolation and sensitive fields.
2. View test: 48-dp pinned Add and three original candidates coexist inside the same fixed-height bar; toolbar can still open, and accessibility describes exact word/language. Add→Undo and storage failures are observable and honest.
3. First-use hint appears once on an eligible inline offer (or after-Space fallback) and remains documented in Settings; dismissing or continuing typing does not save any word.
4. Full JVM/Python gates, signed ARM64 in-place update from v0.10.0, installed ET and EN typing/Add/Undo/Space plus password/private field checks; restore initial Gboard and foreground app. No human-swipe accuracy or real-device latency claim without comparable evidence.
